# Proxy 标签工程 · 整体架构 v1（2026-10-08）

目标（用户）：把用户的**全部行为**——发帖、参加活动、聊天、应用停留、浏览轨迹……——变成**成千上万个**可解释的细标签，
给撮合和推荐用，并让运营看得见、管得住。不是几个字段，是一条管线 + 一本词典。

## 1. 分层（规格 §2–§3：Event = 事实，Feature = 数值，Tag = 可解释状态）

```
行为源 ──► 事件层(Event) ──► 条目打标(Item Tagger) ─┐
 帖子/活动/聊天/页面/轨迹…      append-only，带同意      │  条目 × 标签（词典驱动）
                                                      ▼
                          用户×条目 交互权重 ──► 聚合(User Aggregator) ──► 用户标签(User Tag)
                          (看/赞/评/转/报名/下单)     时间衰减 + 同意过滤        + 特征(Feature)
                                                                                 │
                              运营：词典治理 / 覆盖 / 画像 / 评估  ◄──────────────┴──► 撮合 / 推荐读取
```

**关键设计：标签数量来自「条目标签 × 用户行为」，不是为每个用户手写规则。**
一个用户的标签 = 他碰过的每个条目（帖子、活动、店、创作者、服务、订单）身上的标签，按交互强度和新近度加权后累加。
词典有 N 个节点，用户就可能有 N 个标签；再加上实体级标签（具体的店、具体的创作者、具体的活动类目），上万是自然结果。

## 2. 词典（Taxonomy）——标签的唯一来源
- 层级节点：`domain › category › topic › facet`，如 `interest/outdoor/hiking`、`place/venue/coffee/specialty`、`time/rhythm/weekend_evening`。
  每个节点：稳定 id（路径）、中/越/英名称、父节点、关键词（三语）、状态（ACTIVE / DEPRECATED / MERGED→id）、别名。
- **祖先汇总**：一次碰到 `hiking`，同时给 `outdoor`、`interest` 记（衰减 ×0.5 / ×0.25）→ 同一个人既有细标签也有粗标签，粗细都能被撮合用。
- 治理（词典不是死的）：新词发现（模型 / 日志里出现但词典没有的高频词）→ 候选 → 运营审核入典；合并、废弃、别名在控制台做；每次改动版本化（`rule_version`）。
- **红线节点永不入典**：夜生活、按摩、KTV、陪酒等陪同业务敏感类目（律师清单第 7 条）；校验函数在加载时拒绝。
- 容量目标：v1 ≥ 1,000 节点（话题 / 场所 / 服务 / 时间 / 地点 / 行为模式），逐步到 1 万；实体级（店、创作者）不进词典，按 id 动态生成。

## 3. 行为源 → 事件 → 条目标签（按同意分级）
| 行为源 | 事件 / 来源 | 条目 | 同意 | 现状 |
|---|---|---|---|---|
| 浏览帖子 / 图片 | POST_IMPRESSION、MEDIA_*（含停留） | 帖子（正文→词典） | 采集类目的 | 有 |
| 发帖 | localnet.posts | 帖子 | 主动行为，免 | 有 |
| 互动 | 点赞 / 评论 / 转发 / 收藏（engagement） | 帖子 | 主动行为，免 | 事件有，**未接入标签** |
| 活动 | 看活动页（ACTIVITY_VIEW）、感兴趣、报名 | 活动（标题 / 类目→词典） | 看=采集类，后两者免 | 部分 |
| 市场 | 发单 / 报名 / 被选 / 成单 | 需求（主题→词典）、服务 | 主动行为，免 | 订单有，**需求主题未接入** |
| 场所 | 收藏 / 计划去 / 去过 / 打卡 / 评价 | 店（类型 / 风格 / 区 + 店本身） | 主动行为，免 | 有 |
| 聊天 | 会话**元数据**：会话数、发起比例、响应时延、活跃时段 | 无条目，直接产特征 | 采集类目的 | **未做** |
| 聊天内容 | 正文主题 | — | **单独目的 `CHAT_ANALYSIS`（登记但不开放）**：私人通信内容，未经明确单独同意不做 | 不做 |
| 应用使用 | 前台时长、屏幕停留、屏幕序列（浏览轨迹） | 屏幕 / 功能 | 采集类目的 | **未做（需客户端埋点）** |
| 位置 | 粗粒度网格出现天数 | 区 / 网格 | 采集类 + 定位同意 | 有 |
| 搜索 | 查询词 | 词典命中 | 采集类目的 | **未做** |

## 4. 聚合（用户标签）
`strength(tag) = saturate( Σ_events  w(event_type) × dwell_factor × decay(age, half_life) × ancestor_factor )`
- `w`：浏览 0.3、停留（每 30 秒 +1）、点赞 1、评论 2、转发 2、收藏 2、报名 / 下单 3、自己发 1.5……权重表放配置，运营可调（有留痕）。
- `decay`：指数衰减，半衰期按标签域（兴趣 14 天、场所 30 天、服务 60 天）。TTL 到期自然消失。
- `confidence = n/(n+5) × 来源多样性`；来源标注 BEHAVIOR / EXPLICIT / MIXED；撤回同意后下一轮清除。
- 负向：连续快速划走 → `avoid/<topic>`；显式屏蔽 / 不感兴趣 → 强负向。

## 5. 规模与计算
- **增量重算**：只算「有新事件的人 + 同意变化的人 + 即将过期的人」，用水位线（`tag.compute_state`）；全量重算只在规则版本变化时。
- 存储：`tag.user_tags(user, tag_id, strength, confidence, …)`；万级标签 × 百万用户 → 先按活跃用户裁剪（每人最多保留 top-N，N=300）。
- 读：撮合读 top-K（强度 × 置信度）+ 稀疏向量余弦；运营读聚合（小格子抑制 < 5 人不出数）。

## 6. 运营后台
词典管理（浏览 / 搜索 / 合并 / 废弃 / 别名 / 新词审核）· 管线健康（各源事件量、延迟、覆盖）· 覆盖与分布 · 用户洞察（聚合）· 小美画像 · 撮合预览 / 评估。

## 7. 路线图
- **P1（本期）**：词典引擎 + ≥1,000 节点种子 + 祖先汇总 + 增量重算；互动 / 市场需求 / 活动接入条目打标；聊天元数据特征。
- **P2**：应用使用与浏览轨迹埋点（客户端）+ 屏幕 / 功能标签；搜索词；词典治理页；新词发现。
- **P3**：模型打标（模型底座批处理，给词典外的条目补标签，进候选池不直接入典）；特征库；A/B（共同兴趣权重）。
- 聊天正文分析：不在路线图内，除非单独的同意目的上线并通过法务。

## 8. 合规
所有被动证据统一过 `consent.ValidAtSQL`；主动行为免浏览同意但标注来源；红线节点校验；账号删除连带清标签；
读取按用途（allowed_use）；分群数字小格子抑制；运营看个人详情要权限并留审计。
