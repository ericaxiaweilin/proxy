# 个人主页 vs 设计原型 对比审计（2026-09-18）

范围：`me.tsx` 的 `personalhub` 子页（"个人主页"，对外展示自己的页面），
对照唯一挂在 `CURRENT_BASELINE.json` 上的参考稿
`docs/design/references/proxy_personal_profile_architecture_v5_threads.html`
（PERSONAL_PROFILE_ARCHITECTURE_V5_THREADS，ACTIVE_SCREEN_REFERENCE）。
方法：把参考稿的 JS 状态机切到 `本人`(owner) 视角渲染截图，跟模拟器里
真实登录账号打开"个人主页"的截图逐块比对，不是凭印象判断。

结论先说：**"场景徽章"在参考稿里完全不存在** —— 不是"做得不像"，是这块
从来没有设计稿可以对照，直接解释了为什么它跟页面其它部分脱节。

## 逐块对比

### 1. 头部信息密度：参考稿一行，实现三行

参考稿：`城市 · N 次已履约 · ● 可接单` 一行文字，中点分隔，信息扫一眼就完。

实现（`me.tsx:1912-1930`）拆成三个独立区块：
- 城市单独一个 pill（`personalTopicPill`）
- `— 次浏览 · 最近 30 天 ›`独立一行
- `— 位关注者`独立一行

三行拆开显示、且用户零数据时两行都是裸的 `—`。`FOLLOWER-FACES-001` 的注释
说明这是刻意选择（宁可显示 `—` 也不编假粉丝头像），**这个诚实原则是对的**，
但呈现上一个不带单位、不带说明的破折号，普通用户会读成"坏了"，不会读成
"这是诚实的空态"。建议：至少给这两行一个可点击的"还没有人关注，去动态里
认识新朋友"式空态文案，而不是让 `—` 单独站着。

### 2. 主操作按钮：参考稿有，实现没有

参考稿本人视角头部下方是两个高对比度胶囊按钮：`编辑主页`(黑底白字) /
`分享主页`(lime 底黑字)，是这个页面唯一的强视觉锚点，用户一眼知道"这页
我能做什么"。

实现里personalhub 页头部完全没有对应的主操作行——编辑入口和分享/二维码
被分散到"我的"菜单下的"个人总管理"里（另一个页面），"个人主页"这一页
本身点开之后找不到"编辑"按钮在哪（要退出去另一个入口）。这是个真实的
可用性缺口，不只是好看不好看：参考稿把"编辑/分享"放在你正在看的这页，
实现把它挪走了。

### 3. 场景足迹 挤占了 Bio 的位置

参考稿：头像+名字下面直接是 bio 正文，一段话，完。

实现：头像+名字下面先插一个"场景足迹 ›"的整行 pill 入口
（`personalSceneEntry`，`me.tsx:1895-1903`），bio 被挤到第二位；bio 区
（`personalBio`）自己又在下面重复出现一次 handle
（`↗ weilinxia511`，`me.tsx:1908-1911`）—— 同一个 `weilinxia511` 在这一屏里
出现了三次（标题名字、`@handle`、这个链接行），没有任何一处比另一处更该
被弱化，视觉上没有主次。

### 4. 场景徽章：没有设计稿，图标语言直接跟本页其它图标打架

`场景徽章 · 0/10`（`me.tsx:1945-1967`，样式在 `me-styles.ts:1190-1203`）：

- 图标是裸 emoji 直接当字渲染（`badgeIcon: { fontSize: 24 }`）：📍、🥉🥈🥇
  奖牌、🌊☕🏮🏛️✨ 主题图标混用，字重/描边/配色完全不统一。
- 同一屏的顶部工具栏（分析/搜索/更多）、换头像按钮、场景足迹入口，全部
  用的是 `ProxyIcon` 自家矢量图标系统（同一文件 `me.tsx:1871-1888,1897`）。
  一屏之内两套图标语言并存，这是最扎眼的不协调，换成本项目自己的
  `ProxyIcon` 才是最低成本的修法（不用等设计师出新图，参考稿本身也没画
  过这块）。
- 未解锁态唯一的视觉区分是 `badgeTileLocked: { opacity: 0.55 }`
  ——一个统一 0.55 透明度，卡片背景色、边框都不变。截图里 0/10 全锁定的
  情况下，9 张卡几乎看不出区别，达不到"一眼看出哪些没拿到"的效果。对照
  Duolingo/Steam 成就墙这类"成熟"参照物，锁定态通常是明显的灰度/图标
  蒙版，而不是单纯调透明度。
- 位置优先级：badge 墙紧跟在 bio 后面，先于任何"动态/照片"内容出现——
  参考稿里根本没有这块，但从信息架构角度看，把游戏化内容放在用户真实
  发布内容前面本身就值得商榷。

### 5. 内容 Tab 缺位（已知差距，二次确认）

参考稿本人视角在 CTA 按钮下方是 `动态 / 照片 / 记录` 三 tab（下划线态），
再往下是"分享一点近况…"的快速发帖条，然后才是帖子流。

`IMPLEMENTATION_CONTRACTS.json` 里 `personal-profile` 的 `knownGap`
已经写了"用五 tab 架构替代参考稿的三 tab"——这次实测确认：不止 tab 数量
不同，从我截图能滚动到的范围看，"场景徽章"整块内容在参考稿的信息架构里
根本没有位置，五 tab 版本相当于凭空插入了一屏参考稿没设计过的内容，
而不是"三 tab 换成五 tab"这么简单的差异。

## 建议优先级

1. **P1，低成本高收益**：场景徽章图标换成 `ProxyIcon`，删掉裸 emoji——
   不需要等新设计稿，参考稿本身没有这块，用本项目已有的图标系统统一
   视觉语言即可，最快能让这页"不难看"的一步。
2. **P1**：本人视角补回一行强对比度主操作（至少"编辑主页"要能在本页
   直接点到，不用退出去另一个菜单）。
3. **P2**：头部信息行合并（城市 · 次浏览 · 关注者 一行展示，仿参考稿密度），
   "—" 空态配一句人话文案。
4. **P2**：bio 区去重（场景足迹入口和 bio 顺序对调，或场景足迹收进
   badge 墙区域，别插在 bio 前面）。
5. **P3（需要产品/设计一起定）**：场景徽章要不要留在"个人主页"这个位置，
   还是挪到"场景足迹"详情页里——参考稿完全没规划这块，需要先补一版
   设计稿而不是继续照代码自由发挥。

## 证据

- 参考稿渲染：`docs/design/references/proxy_personal_profile_architecture_v5_threads.html`
  （JS 状态机 `setView("owner")` 切本人视角截图）。
- 实现代码：`apps/mobile/src/surfaces/me.tsx:1858-1970`（personalhub 分支）、
  `apps/mobile/src/surfaces/me-styles.ts:878-903,1190-1203`。
- 模拟器实测：已登录真实账号（`weilinxia511`），"我的" → "个人主页"，
  实拍截图确认头部三行拆分、bio 区重复 handle、badge 墙 emoji 混用、
  锁定态视觉区分不足均为真实渲染结果，非代码推断。
