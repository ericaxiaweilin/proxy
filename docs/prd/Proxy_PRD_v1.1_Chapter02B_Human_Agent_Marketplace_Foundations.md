# Proxy PRD v1.1
## Chapter 02B — Human Agent Marketplace & Local Economy Foundations

**文档类型**：增量细化 PRD / Cross-cutting Foundation  
**插入位置**：Capability Graph / Real-world Scene Network 之后，Task / TaskSlot / Order State Machine 之前  
**本章定位**：作为 Proxy 后续所有产品、业务、数据、安全、商业化章节的上位约束。  
**核心问题**：Proxy 到底是什么、培养什么用户习惯、保护什么数据、优化什么交易、如何形成“人赚钱 + 人消费 + 商家赚钱”的长期经济循环。

---

# 1. 核心定义

Proxy 是：

> **泛场景真人代理（Human Agent）撮合与现实执行平台。**

这里的 Agent 必须是：

> 一个真实的人，在指定时间、地点，以明确角色替 Requester 出现、执行、代表、协助或完成现实任务。

Proxy 不是：

```text
AI Agent Platform
Recruitment Platform
People Browser
Dating / Social App
Creator-only Marketplace
Pure Gig Labor Platform
Merchant ERP
CRM-only SaaS
POS System
```

---

# 2. 真人 Agent 的交易本质

Proxy 不交易“人本身”。

交易对象永远是：

```text
现实任务
+
明确角色
+
时间
+
地点
+
能力要求
+
交付
+
价格
+
履约结果
```

Human Agent 是完成任务的真人执行者。

因此：

```text
Task First
People Second
```

是长期硬规则。

# 4. Proxy 的三边网络

长期平台不是简单双边 Marketplace。

完整结构：

```text
Consumer / Requester
        ↕
      Proxy
     ↙     ↘
Human Agent  Merchant
```

三类角色可能由同一个人承担。

例如：

```text
一个用户
├── 平时作为 Consumer 消费
├── 周末作为 Human Agent 赚钱
└── 未来自己开店后成为 Merchant
```

因此平台身份流转必须允许：

```text
Consumer ↔ Human Agent ↔ Merchant
```

# 5. Proxy Local Economy

Proxy 长期目标不是“做更多商家 SaaS 功能”。

而是建立：

> **一个让真实的人获得收入、让收入进入真实消费、让商家获得交易并再次产生 Human Agent 需求的本地经济循环。**

核心：

```text
Human Agent Earn
↓
Wallet / Income
↓
Consumer Spend
↓
Merchant Revenue
↓
Activity / Demand Growth
↓
Human Agent Need
↓
Human Agent Earn
```

# 72. Acceptance Criteria

## AC-FOUNDATION-01
所有 Agent 必须是真人执行主体。

## AC-FOUNDATION-02
Proxy 不得退化成无 Task 的 People Browser。

## AC-FOUNDATION-03
Task First, People Second 为全局硬规则。

## AC-FOUNDATION-04
Requester / Agent / Merchant 三边必须共享统一交易主链。

## AC-FOUNDATION-05
所有 Human Agent Demand 最终必须进入 Task / TaskSlot / Order。

## AC-FOUNDATION-06
平台核心北极星是 Successful Human Executions，而非 Profile Views。

## AC-FOUNDATION-07
Agent 侧核心习惯必须围绕 Availability → Offer → Earn。

## AC-FOUNDATION-08
Requester 侧核心习惯必须围绕 Need → Task → Completion → Repeat。

## AC-FOUNDATION-09
Merchant 功能优先服务 Demand / Revenue / Human Agent Work / Repeat。

## AC-FOUNDATION-10
Store / Membership / Scene 等未来模块不得演变成脱离 Marketplace 的独立 ERP。

## AC-FOUNDATION-11
Agent Earnings、Membership Points、Proxy Credits 必须账务分离。

## AC-FOUNDATION-12
用户可以在 Consumer / Agent / Merchant 身份之间合法流转。

## AC-FOUNDATION-13
任何真人数据返回必须遵守 Purpose-bound Disclosure。

## AC-FOUNDATION-14
D4 / D5 数据不得进入普通 Candidate API。

## AC-FOUNDATION-15
高敏数据访问必须具有 Task / Order / Purpose / TTL / Audit。

## AC-FOUNDATION-16
用户行为学习必须优化真实任务成交与履约，不优化 People Browsing。

## AC-FOUNDATION-17
Outcome Graph 必须以真实 Task / Slot / Execution 结果为依据。

## AC-FOUNDATION-18
Off-platform 防绕开策略不能只依赖隐藏联系方式，必须创造持续平台价值。

## AC-FOUNDATION-19
Boost 只能影响 Qualified Exposure，不能购买 Eligibility。

## AC-FOUNDATION-20
所有扩展业务必须优先复用统一 Task / Slot / Order 主链。

# 73. 本章锁定结论

1. **Proxy 是真人 Agent Marketplace，不是 AI Agent、招聘、交友或普通 SaaS。**
2. **平台最终优化的是 Successful Human Execution。**
3. **用户行为习惯必须围绕现实 Need、Availability、Repeat 建立。**
4. **三边网络为 Consumer / Human Agent / Merchant。**
5. **长期经济模型为 Earn → Spend → Merchant Revenue → Human Need → Earn。**
6. **Merchant OS 只优先做能增强交易循环的能力。**
7. **Agent Earnings、Membership Points、Proxy Credits 严格分离。**
8. **Human Agent Outcome Graph 是长期核心数据资产。**
9. **真人数据按 D0–D5 分级，并执行 Purpose-bound Disclosure。**
10. **People Browsing 不是增长目标。**
11. **Business Matching 以 TaskSlot Fill / Execution 为核心。**
12. **Merchant / Social / Scene / Membership 必须作为主链扩展，而不是独立系统。**
13. **未来每一个产品功能都必须通过 Habit / Safety / Matching 三问。**
