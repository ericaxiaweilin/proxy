Tag Center · 细粒度标签仓

先保留真实差异，再让数据决定是否归并
建模原则： 不强制把几万种标签先塞进少数“高级人格类别”。标签首先是对真实行为、交易、场景、偏好和状态的具体描述。允许同义、相近、短生命周期标签并存；通过共现、转化、留存和模型效果再决定是否合并。分类只用于导航，不作为真相。
v7 Runtime Rule： Tag namespace 可以持续增长，但 User×Tag 在线状态必须分层。历史标签进入 Cold，当前有效标签进入 Warm，只有与当前 Event/Context 相关的 Hot Decision Set 才允许进入 /v1/decisions/evaluate。标签多 ≠ 每次全量读取。

Feature 使用边界

内部工程约束
Data ≠ Visible Data ≠ Matchable Data.
每个特征必须记录来源、置信度、更新时间和允许用途。用户主动声明、交易事实、观察行为、AI 推断不能合并成同一种“事实”；用于推荐、撮合、商家定向、风控的权限也应分别控制。

Decision Engine lineage: 任何系统曝光产生的 click / save / redeem 必须挂 decision_id + exposure_id。 system_exposed evidence 与 organic evidence 分开计权；缺少 lineage 的系统行为默认只能进入 LEARN_ONLY，禁止直接提升强决策置信度。

Clarification Gate
Clarification 用来完成已存在的 Intent，不允许拿来制造 Intent


        

          

            
ALLOW · Inline

            
用户主动进入任务；缺失字段会显著改变匹配/可行性；当前 session 内轻量询问。

          

          

            
ALLOW · Task-blocking

            
例如已明确“周六去宁平”，但时间完全缺失；不问就无法形成有效 Plan。

          

          

            
PASSIVE ONLY

            
Intent 来自弱推断；可以在用户主动打开相关 Surface 时提供可选筛选，不主动 Push。

          

          

            
FORBIDDEN

            
仅因为模型“想知道更多”而主动 Push 用户，或借问询制造新的偏好证据。

Reward Boundary
Outcome 必须按原因拆解，防止错误学习

        
禁止：`not_fulfilled → reward = -1 → 所有上游模型一起背锅`。
正确：先 Attribution，再将可学习信号路由到 Gravity、Resource、Supply、Ranking、Orchestration、Trust 或 Platform。无法归因时保留 `UNKNOWN`，不要制造假原因。
